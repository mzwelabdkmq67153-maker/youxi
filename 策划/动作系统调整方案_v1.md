日期：2026-11-26　｜　范围：玩家可见角色（PVP 对手、联机队友、PVE 敌人）+ 第一人称手感
状态：**方案待拍板，本轮不改代码**

---

## 0. 一句话结论

十职业 P1 全部换成 Tripo 静态单网格（`*_hero.glb`，1 node / 1 mesh / 0 skin / 0 clip）之后，动作能力的瓶颈已经不在参数表，在资产层。现在全员实际在跑的是"整块刚体抖动"——呼吸 1cm、踏步 3cm、前倾、受击后仰、攻击前冲，五个自由度，调参数调到极限也还是纸板人。

建议路径：**用 Tripo 的免费 rig-check 抽 3 张验证绑骨（0.25 人日）→ 通过就走 B 路线（10 张 hero 绑骨 + 复用现有叠加层）→ 不通过再退 A 路线纯程序化补强**。这是唯一能同时解决"读招"和"打击感"的路径，且成本可控在 2 周内。

## 1. 现状盘点（实测，非估算）

### 1.1 两条动作轨，其中一条已经废了

| 轨道 | 触发条件 | 实现 | 现在谁在用 |
|---|---|---|---|
| **静态轨** `glb3d.js: staticMotion()` | 模型无 `skin` | 根节点微位移 | **全部 10 个职业 + 全部敌人**（正式游玩 100%） |
| **骨骼轨** `glb3d.js: overlay()` | 模型有骨骼 + clip | mixer 播 Idle + 四元数增量叠加 aim / slash / shoot / cast / hit | 只有 `?hero=idle` 降级路径 |

`overlay()` 里那套参数是现成的、可用的：挥砍肩前摆 ≤1.10、外展 ≤0.70、肘 ≤1.25、胸转 ≤0.26；射击肩抬 0.45、肘 0.70/0.75、后坐 0.08；施法胸后仰 0.05、头抬 0.06。**这套代码现在只是没人喂它骨骼模型。**

### 1.2 静态轨的实际参数（全部硬编码在一个函数里）

| 量 | 当前值 | 备注 |
|---|---|---|
| 踏步幅度 amp | 0.030 m | `speed > 0.4` 才切 |
| 踏步频率 freq | **5.2 Hz 恒定** | 速度 1 m/s 和 9 m/s 同频 |
| 待机呼吸 amp / freq | 0.010 m / 1.35 Hz | |
| 移动前倾 lean | `0.02 + speed × 0.026`，≤ 0.16 rad | |
| 侧摆 roll | `sin(0.9t) × 0.015` | |
| 受击后仰 | `-0.18 × hitT`（单档） | hitT 是 1→0 衰减 |
| 攻击曲线 | 前 35% 蓄力 `-0.06` → `sin × 0.22` 前冲 → 0.2 s 回位 | 位移 `lunge × 1.2`（约 0.26 m） |
| 射击 | 同攻击 × 0.4 | 无后坐节奏 |
| 施法 | 同攻击 | 无抬手 |

### 1.3 动作覆盖矩阵

| 动作 | 静态轨（当前全员） | 骨骼轨（降级） | 判定 |
|---|---|---|---|
| 待机 | 呼吸 + 微侧摆 | Idle clip（骨骼 Idle，手臂有动） | 勉强 |
| 走 / 跑 | 踏步，**频率与速度脱钩** | clip timeScale 1→1.6 | 差 |
| 起跑 / 急停 | **无** | 无 | 缺 |
| 转身 | **硬切**（一帧 180°） | 硬切 | 缺 |
| 跳跃 | **无**（敌人 `onGround: true` 恒真） | 无 clip | 缺 |
| 落地 | **无**（只有玩家有 `landEffect` 粒子） | 无 | 缺 |
| 轻击 / 重击 | **同一套曲线**，全职业共用 | slash 一套 | 差 |
| 射击 | 攻击 × 0.4 | 举枪 + 后坐 | 中 |
| 施法 | 同攻击 | 仅躯干微动（mage 因权重禁手臂） | 差 |
| 受击 | **单档 -0.18** | 单档，分 spine/chest/head | 差 |
| 硬直 / 击退表现 | 无（只有 position 位移） | 无 | 缺 |
| 死亡 | **立即 `scene.remove` + dispose** | 同 | 缺 |
| 连段 / 收招 | 无 | 无 | 缺 |

第一人称侧：`updateWeaponVisual()` 只有一条 0.22 s 单峰曲线（`k = sin(πt)`，位移 `-0.05 y / +0.1 z`，旋转 `-0.85 x / +0.2 y / +1.0 z`），**六个近战职业共用**；待机 bob 0.6 cm / 0.5 cm，疾跑横向 ±2 cm。

## 2. 三个根因（按可修性排序）

1. **资产**：hero 是单网格，没有可驱动部位。这是死结，参数层改不了。
2. **参数**：步频不随速、受击单档、攻击一套曲线覆盖六职业——这些是纯参数问题，1 天内可修完。
3. **流程**：死亡直接 dispose（无演出）、敌人 `onGround` 恒 true（无跳跃/落地）、`spawnRing` 落地粒子写死 `y = 0.14`（在 5.72 m 台面的世界里会落在台基上，和上一轮修的"分层"是同一类 bug）。

## 3. 三条路线对比

| | A · 程序化补强 | B · hero 绑骨（半资产） | C · 全资产动画 |
|---|---|---|---|
| 做法 | 扩展 `staticMotion`：pivot 链、步频随速、三段跳跃、受击三档、死亡倒地 | Tripo rig-check → auto rig（7 类生物，人形优先，~30 s/张）→ 复用现有 `overlay()` | Blender 手工绑 + 每职业 6 clip，统一骨架重定向 |
| 能解决 | 步频、起停、转身、跳跃、受击分档、死亡、相机手感 | 以上全部 + **手臂读招**（挥砍弧线/抬枪/结印/收招） | 全部 + 布料/披风/表情 |
| 解决不了 | 手臂动作（单网格不可拆）、武器轨迹、施法结印 | 披风/长袍权重（Tripo 对多层衣物会崩） | — |
| 工时 | 1.5 人日 | 绑骨 1.5 + 动作重定向 3 + 接入 0.5 ≈ 5 人日 | 8–10 人日 |
| 风险 | 整块弯腰像纸板人；读招缺失导致 PVP 不公平 | Tripo 对大武器/长袍的权重可能翻车，需先抽检 | 周期长，阻断其它系统 |

**推荐：B 为主，A 全部照做。** 理由两点：
- A 里除了"手臂"以外的项（步频、跳跃、受击、死亡、相机）B 也不能自动获得，必须单独写，所以 A 不是 B 的替代品，是前置。
- B 的接入成本几乎为零——`overlay()` 的五档参数、`bindings` 的骨骼名映射（`Chest / Spine / Head / UpperArm.R / LowerArm.R`）已经在跑，缺的只是带 skin 的模型。

## 5. 动作规格表（可直接写进代码，数值以现值为基线）

### S1 步频随速（替换 `freq 5.2 恒定`）
```
freq  = clamp(speed / 1.72, 1.20, 5.40)     // 步幅 1.72 m；1.2 m/s 走 = 1.2 Hz，9 m/s 跑 = 5.2 Hz
amp   = clamp(0.010 + speed * 0.0025, 0.010, 0.032)
phase = 累计相位（不要用 t * freq，会跳相）
```
验收：速度 1 / 4 / 9 三档截图，脚部起伏幅度 1.0 / 2.0 / 3.2 cm。

### S2 起跑 / 急停
- 起跑：`lean` 0.12 s 内从当前值推到 0.19（过冲），0.10 s 回落 0.16；同步 `amp` 0.010→0.030。
- 急停（速度 > 5 → < 1 且按键松开）：`lean` 0.18 s 内反向 -0.05，再 0.22 s 回零；`inner.position.z` -0.06 m 做"刹车"。
- 落地后 0.12 s 内 `amp` 归位。

### S3 转身侧倾
```
ω = yaw 变化 / dt（rad/s）
roll = clamp(ω * 0.035, -0.30, 0.30)    // 顺时针转内倾
目标 play 0.25 s 跟随（当前是急停）
```
硬切问题：`rotation.y` 已按 `atan2(dx,dz)` 逐帧算，本身是连续的；"硬切"来自 AI 转向瞬间改变目标方向。做法：给敌人加 `turnRate = clamp(当前→目标角差, 6 rad/s)` 限速。

### S4 跳跃三段（现物理：vy 11.6、G 42 → 滞空 0.552 s、峰高 1.60 m）
| 段 | 时长 | 表现 |
|---|---|---|
| 起跳压缩 | 0.10 s | `inner.position.y` -0.06，`lean` +0.04 |
| 滞空 | 0.35 s | `lean` -0.05（后仰），`amp` 0 |
| 落地压缩 | 0.10 s | `y` -0.10 → 0，`amp` 0.02 抖一次 |
玩家第一人称：落地相机下沉 0.12 m、俯角 +0.5°，0.10 s 恢复。
敌人：`onGround` 改为由 `e.pos.y` 与 `groundBase` 差判断，不再恒 true。

### S5 受击三档（替换单档 -0.18）
| 档 | 触发（单次伤害 / maxHp） | 后仰 | 时长 | 额外 |
|---|---|---|---|---|
| 轻 | < 5% | 0.10 rad | 0.12 s | — |
| 中 | 5–15% | 0.22 rad | 0.20 s | 侧偏 `rand(±0.06)` |
| 重 | > 15% | 0.38 rad | 0.26 s | 后退 0.18 m、`amp` 抖 0.03 |

### S6 死亡倒地（替换"立即 dispose"）
```
0.00–0.32 s  绕 X 轴 -π/2（ease-out），身体下沉 0.10 m
0.32–0.45 s  继续下沉 0.25 m，材质 opacity 1→0
0.45 s       dispose
```
PVP 里尸体挡视线 → 建议尸体"半透明 0.35 + 不参与碰撞"，或 0.45 s 后直接淡出（本方案取后者）。
性能：同屏最多 8 具，0.45 s 内不产生新 draw call。

### S7 攻击三档前摇（读招的基础）
| 档 | 前摇 | 命中 | 收招 | 总时长 | 备注 |
|---|---|---|---|---|---|
| 轻击 | 0.10 | 0.12 | 0.10 | 0.32 | 连点手感 |
| 重击 | 0.20 | 0.14 | 0.18 | 0.52 | PVP 前摇不按 0.75 缩放，保证可读 |
| 技能 | 0.28 | 0.16 | 0.26 | 0.70 | 施法抬手（B 路线后才有手臂） |
现有 0.22 s 单峰介于轻/重之间，是所有职业共用值。前摇期间在模型头顶加一圈收缩环（复用 `spawnRing`，0.28→0.9 半径），把"要出招"变成可见信息。

### S8 连段
同一目标 0.5 s 内接第二段：幅度 ×1.15、时长 ×0.85、`lean` 幅度 ×1.1。第三段回到基础值（防无限加码）。

### S9 施法与射击的差异
- 射击：枪口后坐上抬 0.08 rad，0.06 s 回位；每 3 发加一次 0.15 rad 的枪身侧摆（连发节奏）。
- 施法：胸后仰 0.05、头抬 0.06（与 `overlay()` 现值一致），**静态模型下用"整体后仰 0.06 + 微弱上浮 0.02 m"近似抬手**，B 路线后直接用真手臂。

### S10 第一人称手感（按武器类型分曲线）
| 武器 | 现有 | 建议 |
|---|---|---|
| 短刃（blade / assassin） | 0.22 s 单峰 | 0.26 s、`rx -0.85` 保留，加 0.04 s 起手反向小回拉（-0.12） |
| 巨剑（greatsword） | 同上 | 0.46 s、弧度 `rx -1.05`、`rz 1.35`、位移 `+0.16 z`（沉重感） |
| 长棍（monk） | 同上 | 0.34 s、`rz` 主导（横扫），`rx` 只 -0.35 |
| 拳（boxer） | 同上 | 0.18 s、纯 z 直推，无旋转 |
| 枪（gunner / sniper） | 同上 | 0.10 s 后坐，`rz 0.35`，无大弧 |
| 法（mage / frost / priest） | 同上 | 0.30 s 抬手，`rx -0.55` + 上浮 0.03 |

同一条 `updateWeaponVisual` 用 `WEAPON_ANIM[cls] = {dur, rx, ry, rz, dz}` 配置化即可，不改结构。

## 6. 需要拍板的四件事

1. **走 B 还是纯 A**。B 的前提是抽检 3 张绑骨不翻车（0.25 人日就知道答案）。建议先跑抽检再定。
2. **PVP 前摇预算**。重击前摇 0.20 s 意味着对手有约 5 帧反应窗口；如果你要"秒出手"的爽感，就把 PVP 前摇压到 0.14 s，代价是读招失效、纯拼网速与反应。
3. **死亡是否留尸**。留 0.45 s 有分量，但在 PVP 台面上会挡视线；不留则回到"瞬间消失"，击杀反馈会空。
4. **敌人是否一起绑骨**。12 个敌人 type 走同一套 auto rig 成本翻倍（+1.5 人日），收益是"敌人也会抬手"，但 PVE 里敌人多为石像/异形，Tripo 对非人形权重风险更高。建议**敌人先只用 A 档**。

## 7. 验收口径

- **调试参数**：新增 `?animdbg=1`，每帧把当前状态机（idle / walk / run / start / stop / jump / land / atk_l / atk_h / cast / hit_轻/中/重 / death）、剩余时间、`amp/lean/roll` 写到 `document.title`，与 `?ydbg=1` 并存。
- **关键帧截图 6 张**（无头 Chrome）：起跑 0.12 s、跳跃顶点、落地 0.03 s、重击命中帧、重受击 0.10 s、死亡 0.25 s。
- **性能预算**：26 敌同屏，静态轨每帧 < 0.3 ms；骨骼轨（B 后）每帧 < 2.0 ms（23 骨 × 26 实例）。
- **回退**：`?hero=flat` 强制静态轨，用于对比与最坏情况；B 上线后 `?hero=idle` 可废弃。

## 8. 顺手修（与本方案同源的 bug）

- `spawnRing(..., 0.14, ...)`、`landEffect` 里的 `y = 0.02`：在 `deckTop = 5.72` 的竞技场/主城世界里会落在台基，需要加 `groundBase`。上一轮修的是"人和道具分层"，粒子是第三处同类问题。
- 敌人 `Hero3D.update(..., onGround: true)`：跳跃语义失效，改成按高度差判断。
- `?ydbg=1` 的诊断字段建议并入 `?animdbg=1`，别维护两套。
