# 第七竞技场 · SEVENTH ARENA

第一人称 3D 竞技场原型。一个本地网页就能跑，包含 **PVE 副本** 与 **PVP 对决** 两种模式，支持剑客 / 枪手 / 术士三个职业。

## 运行

方式一：直接双击 `index.html`（Chrome / Edge 均可，`file://` 下也能跑，因为不加载任何外部资源）。

方式二：用项目自带的本地服务器（推荐，行为最接近线上）

```powershell
cd 游戏
node serve.js          # 默认 http://localhost:8080
node serve.js 8123     # 或指定端口
```

`serve.js` 只监听 `127.0.0.1`，同网段其他设备访问不到；对 `..` 目录穿越、畸形百分号编码返回 400。如果要让同事试玩，改用 `python -m http.server` 并自行控制防火墙。

依赖只有本地 `vendor/three.min.js`（Three.js r128），不联网也能玩。

## 模式

**PVE 副本**：波次刷怪，逐波增强，每 5 波出现 Boss。死亡即结算，记录抵达波次与击杀数。

**PVP 对决**：与 AI 对手（Duelist）1v1，先到 3 杀获胜。AI 会保持距离、侧向绕行、射击，并非站桩靶子。

**局域网对战**（真人对真人）：同一 WiFi 下两台电脑，各自填同一个房间号即可 1v1。需要先起联机服务端，见下面「局域网联机」。

## 局域网联机

```bash
# 房主的电脑上起服务端（同端口既是网页也是 WebSocket）
node server.js 8123 --lan     # 局域网模式，会打印本机 IP
# 双方浏览器打开 http://<房主IP>:8123
```

- 只在本机自己试：`node server.js 8123`（只监听 127.0.0.1），两个浏览器窗口都开 `http://localhost:8123`。
- 房主先点「局域网对战」→ 填昵称 →「进入竞技场」，页面给出 4 位房间号；对手填同一个房间号进来，双方自动开打。
- 房间上限 2 人，满员/已结束会收到明确提示；对手掉线会回到等待面板。
- 局域网连不上先看 Windows 防火墙有没有放行 node.exe 的入站连接。

**网络架构（有意取舍）**：位置与朝向由客户端按 20Hz 上报，服务端只仲裁血量、比分、胜负与复活。这样不用把整局战斗搬进服务端，代价是不防改包——定位是局域网朋友对打，不是公开匹配。

| 消息 | 方向 | 作用 |
|---|---|---|
| `hello` → `welcome` | C→S / S→C | 客户端就绪后握手，服务端下发 id、职业血量、出生点、房间比分 |
| `opponentJoined` / `opponentLeft` | S→C | 对手进出房间 |
| `state` | C→S→C | 位置/朝向/动作（idle/run/jump/attack），客户端做插值 |
| `hit` | C→S→C | 上报伤害，服务端 clamp 后扣血并回执 |
| `kill` / `respawn` / `matchEnd` | S→C | 击杀播报、复活、结算 |

**角色形象**：敌人不再是无面几何块，改由 `art.js` 组装低模人形——双腿、躯干、肩甲、头盔、面罩发光条、脚步识别环，按类型分五套配色与剪影：

| 类型 | 剪影 | 配色 |
|---|---|---|
| 近战兵 | 轻甲、单刃短剑 | 深蓝甲 + 红刃口 |
| 枪手 | 窄肩甲、长管步枪 + 枪口能量点 | 琥珀甲 + 金刃口 |
| 精英 | 加宽肩甲、披风、加长巨剑 | 铁锈甲 + 橙刃口 |
| 首领 | 体量 1.85 倍、四尖刺冠、披风、巨刃 | 暗红甲 + 品红刃口 |
| 决斗者 | 轻装、细剑 | 青绿甲 + 青刃口 |

几何与材质模板共享，每具身体只克隆自己的材质副本，因此受击闪红只作用于被命中的那一只。

**本轮换代**：敌人全部换成与玩家同一套人形骨架（7.5 头身、总高 1.80），按类型换配色、肩甲、披风、盔脊与武器：

| 类型 | 剪影 | 实测 |
|---|---|---|
| 杂兵 | 单刃剑、窄肩甲 | 1151 面 / 3 mesh |
| 射手 | 横压步枪 + 枪口能量点、肩甲加宽 | 1280 面 / 3 mesh |
| 精英 | 加宽肩甲、披风、盔脊、巨剑 1.10 | 1204 面 / 3 mesh |
| 决斗者 | 轻甲、青绿刃口步枪 | 1280 面 / 3 mesh |
| 首领 | 体量 1.85 倍、披风、盔脊、巨剑 1.34 | 1204 面 / 3 mesh |

合批后每只 3 个 mesh（cloth / armor / accent），旧版是 22–27 个，drawcall 与面数一起降下来；面数与玩家三职业（1316–1472 面 / 4 mesh）同量级。

**动作系统**：跳跃（重力 16、起跳初速 6.4，起跳与落地各有一圈地面波纹与粒子）、疾跑（1.45 倍速度、每秒耗 24 耐力、停下按 14 回复、沿途留残影）、空中可躲开近战横扫。

**战斗特效**：近战随挥砍方向铺开的扇形斩击弧、枪手射线前端的枪口火光、术士法阵与投掷法球的拖尾、击杀时的碎片飞散、技能冲击波与屏幕震动。

客户端：菜单 / PVE / PVP / 三职业 / 结算 / 重生 / 暂停 实测可进入，无控制台报错。

本轮修掉的问题：

1. `serve.js` 用 `startsWith(ROOT)` 做前缀判断，同级同名目录（如 `游戏2\`）可被读取 → 改为 `path.relative` 段级校验。
2. `serve.js` 的 `decodeURIComponent` 未捕获异常，一个畸形 URL 就能让服务进程退出 → 加 try/catch。
3. `serve.js` 监听全网卡 → 改为仅 `127.0.0.1`，并补 `nosniff`、`HEAD`、`Content-Length`。
4. 柱子遮挡用包围球判定，射线在 y≈1.2 处打过去也不会被 4.4 米高的柱子挡住 → 改为圆柱求交。
5. 投射物命中只比水平距离，朝天打的法球能命中地面敌人 → 加高度带 `0.1~2.4`。
6. 近战敌人隔柱打人 → 加水平视线检查 `losBlocked`。
7. 每局重建武器时旧武器只从相机摘除、不释放几何与材质 → 补 `disposeGroup`。
8. 菜单里按住的 WASD 会带进新一局 → `startGame` 清空按键状态。
9. 切到后台时游戏继续跑，人是离开的却掉血死亡 → `visibilitychange` 自动暂停。

## 打击感（GDD-COMBAT-HITFEEL-001）

`hitfeel.js` 单独一层，只负责"判定命中之后怎么演"，不改任何判定与伤害数值。

| 档位 | 触发 | 顿帧 | 震屏 | 推镜 | 闪白 |
|---|---|---|---|---|---|
| light | 普通命中 | 0 | 0.03 / 0.05s | 无 | 无 |
| heavy | 重击、第 3 段连段 | 1–2 帧 | 0.08 / 0.10s | 0.08 | 无 |
| crit | 暴击、击杀 | 3 帧 | 0.15 / 0.14s | 0.08 | 0.55 |

- **空挥不演**：`HitFeel.whiff` 只出风声，不出撞击音、震屏、冲击波、闪白。
- **同目标节流**：同一目标 3 帧内只播一套完整特效，避免连射刷屏。
- **顿帧不冻 UI**：顿帧只压 `anim` 里的模拟步长（`dilation()` 返回 0.15/0.05），HUD、音频、网络上报照常走真实时间。
- **调试面板**：F3 或任意 URL 加 `?hf` 展开，显示帧号、分节、档位、判定窗、顿帧、震屏与最近 6 条命中记录；八项开关可逐条关掉验证"关掉特效不动判定"。

命中到表现在已核对：判定帧内出特效，镜头位移与震屏叠加后不超过单次幅度上限。

**目录**：

- 资产：`art/模型/glb/`（三职业 2K 与 `*_1024.glb`、`inventory.json`）；预算口径见 `art/模型/GLB_资产预算_v1.md`。
- 加载器：`glb3d.js`（工程根，与 `real3d.js` 同级）；依赖 `vendor/GLTFLoader.js`、`vendor/SkeletonUtils.js`。
- 局内验收页：`_ingame_glb.html`（自动开局 + 性能 HUD + 调试钩子 `window.__glbDbg`，调试逻辑不进 `index.html`）。
- 实机截图与采集数据：`_shots/glb_ingame_*.png`、`_shots/glb_ingame_metrics.json`；验收清单与实测明细见 `art/模型/GLB_实机验收_v1.md`。

**实测结论（桌面参考，2026-11-23，本地 8091 端口）**：

- 加载体积：敌人 1024 三份 GLB 合计 5.87 MiB（6,159,028 B）；全 2K 三份合计 11.18 MiB（11,724,308 B）。冷启动首挂本机约 0.28–0.62 s/份；缓存命中后同模型克隆实例化约 0.37–0.68 s/份。
- 渲染（场景遍历口径）：1 主角 + 3 敌人 ≈ 85 draw calls / 70.1 k 三角；1 主角 + 6 敌人 ≈ 104 draw calls / 115.2 k 三角。单模型 14.0–16.0 k 三角、21 骨骼、6 材质。
- 显存（贴图解码驻留口径）：单份 2K 63.84 MiB、单份 1024 15.96 MiB；主角 2K + 敌人 1024 ≈ 111.72 MiB；全 2K 三变体 ≈ 191.52 MiB。
- 骁龙 680（Adreno 610）判断：1+3 敌人 1024 档预计贴近 30 fps、不保证稳 30，爆发帧可能掉到 20–28；1+6 档多数帧低于 30；全 2K 贴图不建议上 680。主瓶颈是 CPU draw call 派发与蒙皮/mixer 更新，其次是像素填充，三角面与贴图带宽最轻。桌面 FPS 仅作相对参考，不能直接当手机帧率。


## 副本掉落 · 六槽装备

**脚本顺序**：`index.html` 里 `loot.js` 必须在 `game.js` 之前（`resetPlayer` 里就会调用 `recalcGear()`）。

**拾取与比较**：走进 1.45 m 自动拾取；同槽评分更高 → 直接装备（旧件按规则处理并 toast 提示），否则进背包（上限 12 件，满了丢评分最低的）。评分权重见 `loot.js` 的 `SCORE_W`（暴击 4.0、伤害 3.0、攻速 2.4、生命 0.42…），只做同槽比较，跨槽不比。

**属性落地**（`recalcGear()`）：伤害/暴击/攻速/攻击距离/减伤/能量回复直接叠到 `player.g*` 字段，由 `tryAttack / meleeAttack / hitscanAttack / damagePlayer / killEnemy` 读取；生命与能量上限、移速、耐力上限按基础值重算。血量按"当前比例"随上限平移，换装不会凭空回满血。减伤封顶 55%。

**键位**：`B` 开关背包（不退出指针锁），`↑↓` 选择、`Enter` 装备、`X` 丢弃、`Esc` 关闭。装备栏常驻右上角，显示六槽与词条合计。

**调试参数**：
- `?loottest=1`：开局在出生点前方摆六槽各一件 + 四件低档同槽，用来验证装备与"入包"两个分支。
- `?nolock=1`：不请求指针锁、失锁与切后台都不暂停，便于自动化走位与截图（正常玩不要带）。

**边界**：装备不绑职业（武器只给通用词条，名字按拾取时职业生成）；PVP 与联机对战不掉落（比分模式没有装备结算）；装备在本局内保留，刷新页面即清空 —— 跨局成长属于"成长存档"待做项。

## 地宫副本 · 小怪与 BOSS

**口径**：只借《全职高手》里公会副本的"机制气质"—— 前排坦克硬吃、法系隔距离放地面预警圈、关底 BOSS 分阶段召唤与范围技 —— **不使用原著角色名、不使用原著立绘**，敌人全部自创命名与配色，走项目自己的四套美术档。

**新增小怪**（`game.js` 的 `TYPES`）：

| 键 | 名称 | HP | 移速 | 伤害 | 半径 | 分值 | 行为 |
|---|---|---|---|---|---|---|---|
| golem | 石傀 | 240 | 1.9 | 24 | 0.86 | 2 | 慢速推进的近战坦克，起手前摇 0.78 s、攻击间隔 1.95 s，砸地额外一圈灰蓝冲击环 |
| swarm | 蚀虫 | 28 | 3.7 | 6 | 0.36 | 1 | 极快极脆的虫群，前摇 0.24 s、间隔 0.78 s，靠数量和贴身缠斗施压 |
| hexer | 咒术师 | 70 | 2.5 | 14 | 0.52 | 2 | 法系，站 9–16 m 外，贴身会后撤；每 3.2 s 在玩家脚下埋 2.9 m 延迟咒缚圈 |

近战分支统一走 `isMeleeType()`（`grunt / elite / golem / swarm`），前摇与攻击间隔查 `WIND_OF`、`CD_OF` 两表，加新近战怪只需补表。

**新增 BOSS**（`BOSS_TYPES = boss / warden / oracle`，都吃 `isBossType` 的波次血量缩放）：

| 键 | 名称 | HP | 移速 | 伤害 | 半径 | 分值 | 站位 |
|---|---|---|---|---|---|---|---|
| warden | 守卫长 | 1100 | 2.5 | 30 | 1.35 | 6 | 7–13 m 持剑压制 |
| oracle | 咒缚主祭 | 950 | 2.2 | 20 | 1.30 | 6 | 10–18 m 远程施法 |

**守卫长的技能循环**：
- 每 2.0 s：`bossBurst` 发出一轮金色弹幕（散射，可侧移躲开）。
- 每 8 s：召 2 只石傀（召唤物计入剩余敌人，因此 BOSS 战会持续加压）。
- 每 10.5 s：`groundSlam` 以自身为圆心 4.4 m、0.9 s 预警的裂地，圈内必须离开。

**咒缚主祭的技能循环**：
- 每 3.0 s：在玩家落点埋**双圈**咒缚（`castHexTrap`，1.25 s 延迟、2.9 m 半径、伤害 `自身伤害 + 12`）。
- 每 8 s：召 3 只蚀虫（虫群封走位）。
- 每 9 s：`bossBurst` 紫色弹幕。

**预警圈是"敌方专属"**。`spawnDelayedBlast` 的第 7 参 `hostile` 决定归属：敌方圈只在玩家处于 `半径 + 0.5` 时打玩家，**不会**误伤自己召唤的小怪、也不会自残；玩家技能的圈仍然只打敌人。这是早期版本的一个设计错误（BOSS 裂地会炸掉自己的召唤物），已修正。

**波次编队**（`buildWaveQueue(wave)`）：

- 数量 `wave 1 取 3，之后 min(30, 3 + wave * 2)`。
- 解锁与权重：蚀虫（第 2 波起，66%）、射手（第 3 波起）、石傀（第 4 波起，50%）、咒术师（第 4 波起，34%）、守关（第 6 波起，18%），保底填充杂兵。
- 每 5 波出 BOSS：第 5 波守卫长、第 10 波咒缚主祭，之后按 `cycle % 2` 交替；**第 20 波起双 BOSS 同场**（按 cycle 奇偶决定出场顺序）。
- 播报按 `TYPES[t].name` 去重拼接：`BOSS 来袭 · 守卫长` / `双 BOSS 来袭 · 咒缚主祭 + 守卫长`。

**辨识标记**（`decorateEnemy`）：四套美术档的模型贴图互不相同，配色差异在 GLB 档里被贴图吃掉，因此 BOSS 与小精英额外挂程序化发光环（加色混合、随时间自转）：守卫长头顶金环 + 脚下金环，咒缚主祭背后两道紫竖环，石傀脚下灰蓝环，咒术师头顶小紫环。这样在写实档 / 低模档 / 水墨档里都能一眼分出层级。

**调试参数**：
- `?wave=N`：从第 N 波起手（clamp 1–60），用来直接跳关底波看编队。
- `?boss=warden|oracle|boss`：清空波次队列，只在正前方 12 m 摆这一只 BOSS，用来单看它的走位、弹幕与召唤（不带 `sandbox` 才能看到咒缚圈真掉血）。
- `?bestiary=1`：把石傀 / 蚀虫 / 咒术师 / 守卫长 / 咒缚主祭并排摆成一行并冻结 AI，用来比对体型与光环。

**实测结论（2026-11-24）**：`?boss=oracle` 单挑场，血量 130 → 98 → 66，确认咒缚圈按延迟起爆并结算到玩家；剩余敌人从 1 涨到 4，确认蚀虫召唤；弹幕球可见。`?boss=warden` 近距离可辨体型约 1.6 倍于杂兵、青色大剑 + 头顶金环。`?bestiary=1` 五只并排层级清楚，蚀虫有意保持极小的体量。

**边界**：小怪与 BOSS 的数值是首版手感值，未做逐波难度曲线校准；召唤物没有数量上限（长局靠玩家的清怪速度压制）；BOSS 不做怒气/狂暴二阶段，双 BOSS 同场只靠出场顺序区分。

## 玩家等级 · 刷本成长

PVE 副本里获得经验、累积等级，**等级跨局保留**，写在 `localStorage` 的 `seventh_arena.progress.v1`。PVP 与局域网对战不结算经验、也不吃等级加成 —— 对局维持职业原始属性，避免靠刷本等级碾压。

**升级需求每级翻倍**（`LEVEL_XP_BASE = 100`、`LEVEL_XP_MULT = 2`）：

| 目标等级 | 本级所需经验 | 累计 |
|---|---|---|
| 2 | 100 | 100 |
| 3 | 200 | 300 |
| 4 | 400 | 700 |
| 5 | 800 | 1 500 |
| 6 | 1 600 | 3 100 |
| 7 | 3 200 | 6 300 |
| 8 | 6 400 | 12 700 |
| 9 | 12 800 | 25 500 |

软上限 20 级（`LEVEL_CAP`）。按上表，第 8 级就要 1.27 万经验，所以"刷满"是长期目标而不是一晚上能做完的事。

**经验来源**（`XP_OF`，击杀值再乘波次系数 `1 + wave * 0.06`）：

| 来源 | 经验 |
|---|---|
| 蚀虫 swarm | 5 |
| 杂兵 grunt / 射手 shooter | 12 |
| 咒术师 hexer | 22 |
| 石傀 golem | 30 |
| 守关 elite | 60 |
| 地宫主宰 boss | 300 |
| 守卫长 warden / 咒缚主祭 oracle | 320 |
| 清完一波 | `50 + 波次 * 20`，BOSS 波额外 +150 |
| PVP 对手 duelist | 0 |

以第 1 波（3 只杂兵 + 清波）为例：约 13 × 3 + 70 ≈ 109 经验，正好够升到 2 级；第 2 波开始要 200，得清两三波才升一级。

**等级加成**（`LEVEL_GAIN`，每级累加，只在 PVE 生效）：

| 属性 | 每级 |
|---|---|
| 生命上限 | +16 |
| 能量上限 | +3 |
| 伤害 | +1.3% |
| 减伤 | +0.5%（仍与装备一起吃 55% 封顶） |
| 移速 | +0.4% |

加成并进 `recalcGear()` 计算，和装备词条同一条链路，所以换装、升级都不会互相覆盖。升级瞬间**回满血 / 能量 / 耐力**，并触发金色环 + 碎片演出与 `等级提升 · Lv N` 播报。

**死亡惩罚**（`DEATH_PENALTY = 'level'`）：

- 副本里死一次 **掉一级**，本级经验清零（`等级下降 · Lv N` 播报，结算面板多一行 `Lv 4 → Lv 3`）。
- **1 级有保护**：1 级死亡不掉级（结算显示"无（1 级不吃惩罚）"），避免新档被清空后卡死。
- 只扣 PVE：PVP 与局域网对战死亡（比分模式那条命）不扣等级。
- 只扣等级，不扣装备 —— 装备本来就只在本局有效。
- 想调成"只清本级经验、等级不动"，把 `DEATH_PENALTY` 改成 `'xp'`；想更狠（掉两级/扣经验倍数）在 `applyDeathPenalty` 里加一行即可。

**UI**：
- 血条上方常驻一条 `Lv N` + 经验条 + `当前 / 需求`，满级显示 `MAX`。
- 主菜单在开始按钮上方显示"玩家等级 Lv N"与进度。
- 结算面板多一行「玩家等级」。

**调试参数**：
- `?lv=4`：直接把等级设到 4（经验清零并写档）。
- `?xp=900`：灌入 900 经验，用来验证连升（100 + 200 + 400 = 700 后停在 4 级 200 / 800）。
- `?resetlv=1`：清掉存档，从 1 级重刷。
- `?die=1`：开局 0.8 秒后强制死亡，用来核对掉级结算与结算面板（不依赖游戏循环）。
- 四个参数都会写 `localStorage`，测完记得用 `?resetlv=1` 复位；注意 `?lv=` 与 `?xp=` 每次开局都会重新执行，想验"掉级后重开"要先刷新到不带参数的地址。

**边界**：等级只加数值，不开放技能点/洗点，也没有装备等级门槛；存档只在本机（换设备或清缓存即归零）；联机时客户端自报等级，服务端不校验 —— 想做成网络游戏的正规成长线，需要把等级搬到服务端（见「尚未实现」）。
